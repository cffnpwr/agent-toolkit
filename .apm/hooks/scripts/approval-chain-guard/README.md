# approval-chain-guard

承認プロンプトが出るシェルコマンドの呼び出しのうち複数のコマンドをつないだものを拒否し、1回の呼び出しで1つのコマンドを実行するよう促すhook。

## Requirements

- [Bun](https://bun.sh) 1.2以上

## 検知する呼び出し

`&&`・`||`・`;`・改行で複数のコマンドをつないだ呼び出しを検知する。

- 承認プロンプトを出す直前（PermissionRequest）に発火するため、承認が必要な呼び出しだけが対象になる。承認が必要かはharnessが決める
- 複合構文（サブシェル・`if`・`for`等）・コマンド置換・プロセス置換の内部も判定する
- パイプ（`|`）・`&`だけでつないだ呼び出しは検知しない
- `cd`の後に`&&`で1つのコマンドだけをつないだ形（`cd <dir> && <コマンド>`等）は通過させる。harnessが呼び出しごとに作業ディレクトリーを戻すためである

## harnessごとの動作

| harness | 検知したときの動作 |
| --- | --- |
| Claude Code | 呼び出しを拒否し、分割の案をCoding Agentに渡す |
| Codex | Claude Codeと同じ |
| Gemini CLI・GitHub Copilot CLI | 対象外 |

拒否の理由には1回の呼び出しに1つずつ分けたコマンドの案を入れる。
機械的に分けられない形（複合構文の内部の連結等）では該当する箇所を示す。
拒否をJSONで返す理由は[ADR 0007](../../../../docs/adr/0007-permission-request-json-decision.md)を参照する。

## 注意事項

- `sh -c 'a && b'`・`eval`等の文字列越しの実行は検知しない
- `[[ a && b ]]`の内部の`&&`はコマンドの連結ではないため検知しない
- 分割すると、`&&`・`||`による条件付きの実行は失われる
- hookを無効化する方法は用意していない
- bunを利用できない場合・依存パッケージの同期に失敗した場合・hook入力を読めない場合は通常の承認プロンプトに戻す
