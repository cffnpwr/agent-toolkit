# Model Selection

作業とモデルの適合を判断するための指標。委譲先のモデル選定はその一形態であり、作業を始める前に「この作業をいまのモデルで行うのが適切か」を確かめる用途にも使う。

## 判定手順

作業の難度帯を次の順で判定し、最初に該当した段に決める。対応するモデルは後述の対応表で引く。

1. **難所** — いずれかに該当する。
   - 複数モジュールに跨る設計判断を含む
   - 並行・非同期・アルゴリズムの正しさが焦点になる
   - 原因が特定できていない不具合の診断を含む
   - 仕様の解釈に自由度があり、誤ったときの手戻りが大きい
2. **定型** — すべてに該当する。
   - 変換規則・手順を事前に列挙できる
   - 正解が一意に定まる
   - 機械的な検証（型・テスト・diffの目視）で正誤を判定できる
3. どちらにも該当しなければ**標準**。

標準は消去法で決まる既定であって「迷ったときの逃げ場」ではない。必ず1・2の判定を先に通すこと。このほか次の補正を掛ける。

- **失敗コスト**: 呼び出し元の検証・レビューで失敗を拾える体制があるなら、境界上の作業は下段へ倒してよい。拾えないなら上段へ倒す。
- **量**: 並行数×イテレーション数が多いほど、下段のコスト差が効く。
- **エスカレーション**: 成果が検証を繰り返し通らないときは一段引き上げる。

## いまのモデルとの適合判断

作業を始める前に、判定手順で得た難度帯といまのセッションのモデルを突き合わせる。不適合なら、そのまま進めず次のいずれかを取る。過小（モデル < 作業）は品質のリスク、過剰（モデル > 作業）はコストと待ち時間の無駄になる。

- 適合する難度帯のモデルのAgentへ委譲する。
- ユーザーへセッションのモデル切り替えを提案する（切り替えはユーザーの操作が必要なので、勝手に切らず提案に留める）。

単発の小さな作業に限り、過剰のままそのセッションで行ってよい。

## 主エージェントのモデル

オーケストレーション・ユーザーとの対話・レビューを担う主エージェント（orchestratorスキルの親など）は、判断が集中するため最上位モデルが適する。セッションのモデルは途中で変えられないことが多いので、Claude Fable 5を主エージェントにする場合はセッション自体をFable 5で起動する。

## 対応表

| タスク像 | Claude | OpenAI |
| --- | --- | --- |
| 定型・機械的: 抽出・分類・単純変換・rename・ボイラープレート | Haiku 4.5（Claude CodeのAgentツールなら`model: "haiku"` / API `claude-haiku-4-5`） | GPT-5.6 Luna（`gpt-5.6-luna`） |
| 標準: 通常粒度の実装（1モジュール・1責務＋テスト）・調査・文書作成 | Sonnet（`model: "sonnet"` / API `claude-sonnet-5`） | GPT-5.6 Terra（`gpt-5.6-terra`） |
| 難所: 複雑なアルゴリズム・設計判断が濃いタスク・深いデバッグ | Opus（`model: "opus"` / API `claude-opus-4-8`） | GPT-5.6 Sol（`gpt-5.6-sol`） |

対応の根拠（確認日: 2026-07-23）:

- Claude: Sonnet 5はSonnetティアの現行最上位で、コーディング・エージェント作業に最適とされる。Opus 4.8はOpusティアの現行最上位。Haiku 4.5は最速・最安の単純タスク向け。出典: [Claude公式モデル一覧](https://platform.claude.com/docs/en/about-claude/models/overview.md)
- OpenAI: 公式のCodexモデルガイドが、Sol=複雑なコーディング向けフラッグシップ、Terra=日常作業のバランス型、Luna=高速・最安の大量処理向け、と位置づけている。GPT-5.6ファミリーは2026-07-09にGA。出典: [Codex Models](https://developers.openai.com/codex/models)（[learn.chatgpt.com/docs/models](https://learn.chatgpt.com/docs/models)へリダイレクト）、[GPT-5.6発表](https://openai.com/index/gpt-5-6/)

モデルのラインナップは更新されるため、この表の鮮度が疑わしい場合は上記の公式ページで現行モデルを再確認してから選ぶ。

### Claude Fable 5の扱い

Fable 5は委譲先の既定にしない。理由: (1) 単価がOpus 4.8の2倍で並行×多数の委譲にはコスト効率が悪い、(2) 難しいタスクでは1リクエストが数分級の長ターンになり待ちが伸びる、(3) 安全分類器による`refusal`があり（サイバーセキュリティ・生物系対象）、セキュリティ隣接のタスクで誤検知があり得る。公式ガイダンスもFableをOpusの既定のアップグレード先とせず、明示選択時のみとしている。

使いどころは次に限る（例: Claude CodeならAgentツールの`model: "fable"`で指定できる）。

- 主エージェントのモデルとして（推奨。前節）
- 難所タスクでOpus 4.8の成果が検証を繰り返し通らない場合のエスカレーション先
- ユーザーが明示指定した場合

OpenAI側にFable相当の上位段は置かない（Codex系の現行最上位はSol）。

## 実行経路

モデルの起動経路は「起動元ハーネスのサブエージェント機構で起動できるか否か」で分かれる。どのプロバイダのモデルが内蔵側になるかはハーネス次第であり（Claude CodeならClaudeモデル、CodexならGPT系、というように）、プロバイダによる固定の区別ではない。

### ハーネス内蔵のサブエージェント機構（優先）

起動元ハーネスがモデル指定付きでサブエージェントを起動できるモデルは、その機構で起動する（例: Claude CodeのAgentツールの`model`パラメータ）。修正イテレーションをSendMessage相当で同一Agentへ送れる。

### 外部CLI経由

起動元ハーネスから直接起動できないモデルは、そのモデルのプロバイダのCLI（codex・claude等）をBashで起動する。実行上の注意:

- **事前に存在確認する**（例: `codex --version`）。CLIが無ければ導入せず、ハーネス内蔵経路の同格モデルへ切り替えてその旨を報告する。
- **フォアグラウンドで完了まで待つ。** 十分なtimeout（目安10分以上）を設定し、バックグラウンド化して早期returnさせない。
- **出力を検証する。** ステータス行・エラーダンプは成果ではない。実質的な成果物が返るまで完了と見なさない。
- **実際に起動したモデルを報告する。** 指定したつもりのモデルでなく、CLIの出力から実測で確認した値を使う。
- **修正イテレーションの制約。** SendMessage相当が使えない。CLIにセッション継続機能があればそれで継続し、無ければ修正指示を含めた指示文で同一の作業対象に対して再実行する（コンテキスト保持の利点は失われる）。呼び出し元のワークフローが同一Agentへの修正往復を前提とする場合（orchestratorスキル等）は、ハーネス内蔵経路で起動できるモデルを優先する。
