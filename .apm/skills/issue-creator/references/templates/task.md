# タスクテンプレート

ユーザーに直接見えない内部の作業（リファクタリング・依存の更新・整理・ドキュメント・インフラストラクチャ）に使う。

```markdown
## 目的
[完了すべき内容を1行で]

## 背景
[このタスクが必要な理由（依存ライブラリのEOL・リファクタリングの結果として判明した等の直接的な契機）]

## スコープ
[このタスクで扱う範囲]
- [扱う1]
- [扱う2]

## スコープ外
[このタスクで扱わない範囲（関連するが別タスクとして分けるもの）]

## サブタスク
- [ ] [サブタスク1]
- [ ] [サブタスク2]
- [ ] [サブタスク3]

## 変更対象のファイル
[変更対象のファイル（コードベースから判明したもの）]
- `path/to/file.ts`

## 完了の定義
[このタスクが完了したと判定できる状態]

## 依存
[このタスクの着手を妨げているものがあれば記載（Issue番号・外部要因等）]

## 補足情報
[参考資料・関連Issue・設計メモ等]
```

## 節の規則

各節の規則を次に示す。

- 目的には、ユーザー価値ではなく技術的な完了状態（「Xを削除する」「Yを最新版に上げる」等）を書く
- 背景には、今やる理由を明確に書く。タスクは緊急性を判断しにくいためである
- スコープ・スコープ外には、境界を明示する。タスクは作業範囲が広がりやすいためである
- 1日以内で終わらない場合は、サブタスクに分ける。各サブタスクを独立して進められるか検討する
- 完了の定義には、観測可能な状態（テスト合格・ビルド成功・ドキュメント更新等）を書く
- 依存が該当しない場合は、節ごと削除する
