# バグ報告テンプレート

プロジェクトに`.github/ISSUE_TEMPLATE/bug*.md`・`.gitlab/issue_templates/bug*.md`が無い場合に使う。

再現手順は必須である。
省略しない。

````markdown
## 概要
[何が起きているかを1行で記述]

## 再現手順
1. [手順1（操作を具体的に）]
2. [手順2]
3. [手順3]

## 期待する動作
[ユーザーが期待した動作]

## 実際の動作
[実際に起きた動作（エラーメッセージ・画面の状態・出力値等を具体的に）]

## 発生頻度
[毎回・たまに・1回だけ（「たまに」の場合は、条件があれば併記）]

## 環境
- OS: [例: macOS 14.5]
- ブラウザー・ランタイム: [例: Chrome 130・Node.js 22.5.0]
- アプリケーションのバージョン: [例: v1.2.3、またはコミットのSHA]
- [その他の関連する環境情報]

## エラー出力
```
[エラーメッセージ・スタックトレース・ログをそのまま貼る]
```

## 関連するコード
[再現に関わるファイルパスと行番号（コードベースを読んで判明したもの）]
- `path/to/file.ts:123`

## 影響
[この問題が誰にどのような影響を与えているか]

## 回避策
[既知の回避策があれば記載（なければ節ごと削除）]

## 補足情報
[関連Issue・最近の変更・再現に役立つ補足情報があれば記載]
````

## 節の規則

各節の規則を次に示す。

- 再現手順は省略しない。ユーザーから提供されない場合は必ず質問する
- 期待する動作は、仕様書から推測しない。ユーザーが何を期待していたかを書く
- 実際の動作は、「動かない」では不十分である。具体的に何が起きたかを書く
- 環境には、ユーザーの環境を書く。自分（AI Agent）の環境を書かない
- エラー出力の機密情報（トークン・内部ホスト名・個人パス）は、プレースホルダーに置換する
- 関連するコードは、コードベースから判明した場合のみ記載する。推測は書かない
- 回避策・補足情報は、該当する情報がない場合は節ごと削除する。「なし」と書かない
